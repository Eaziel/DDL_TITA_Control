## 2. 清理一次性诊断

下面是清理方案，助手没有修改TITA_Lab。2026-10-23最新只读复核：RESET/CONTACT与COST打印已删除，自碰撞显式True；正式钩子保留。仍有Scene.base_contact_debug、首步VIEW打印及cost临时断言待删。当前三文件和完整清理候选均只作AST检查，未运行仿真。

| 位置 | 删除 | 保留 |
| --- | --- | --- |
| VelocitySceneCfg | base_contact_debug及其说明注释 | contact_forces、height_scanner |
| TitaVelocityEnv.step | [VIEW]/[COST]打印、临时cost shape/finite/nonnegative断言 | 历史更新、奖励合成、extras["costs"] |
| TitaVelocityEnv._reset_idx | [RESET]/[CONTACT]整段诊断if | 六维样本和cost的重置前采集、父类reset、历史清理、Episode_Cost统计 |
| TITA_CFG的PhysxArticulationCfg | 临时关闭自碰撞的注释 | 显式enabled_self_collisions=True及原求解器迭代配置 |
| 相机/原生可视化 | 无需随诊断删除 | Kit资产跟随与按需使用的原生debug_vis |

当前临时诊断会将GPU张量转换为Python数值/布尔值，适合排查，不必留在每个训练步中。CostManager.compute已有单项shape检查，正常功能和回合统计继续保留。

将step和_reset_idx替换为：

```python
    def step(self, action: torch.Tensor) -> VecEnvStepReturn:
        """Advance the environment and return task rewards and costs."""

        # 此时 obs_buf 保存的仍是上一次返回的观测。
        self.proprio_history.read_then_push(
            self.obs_buf["policy"],
            self.episode_length_buf,
        )

        obs, reward, terminated, time_outs, extras = super().step(action)

        # 找到本步已经计算好的失败奖励。
        termination_index = self.reward_manager.active_terms.index("termination")
        termination_reward = self.reward_manager._step_reward[:, termination_index] * self.step_dt

        # 普通项合计夹到非负，再加回失败奖励。
        ordinary_reward = reward - termination_reward
        reward.copy_(ordinary_reward.clamp_min(0.0) + termination_reward)

        # 无reset时在这里计算；有reset时返回reset前保存的本步值。
        # clone让本次返回的矩阵不被下一步覆盖，形状(N, 6)。
        extras["costs"] = self.cost_manager.compute().clone()

        return obs, reward, terminated, time_outs, extras

    def _reset_idx(
        self,
        env_ids: Sequence[int] | torch.Tensor,
    ) -> None:
        """Reset selected robots and their task histories."""

        # 重置物理状态前，保留刚结束这一步的六维观测样本。
        self.observation_manager.compute_group("privileged_state")

        # 父类修改姿态、关节速度和传感器数据前，保存刚结束的一步。
        self.cost_manager.compute()

        super()._reset_idx(env_ids)
        self.proprio_history.reset(env_ids)

        # 父类创建本轮log后，再加入cost统计并更新加速度差分基准。
        self.extras["log"].update(self.cost_manager.reset(env_ids))
```

## 3. 可选对照：Gym的碰撞模型是什么

旧实际使用的tita_description.urdf中，机身和两个leg_3均为指定尺寸与局部位置的box：

| 所属刚体 | box完整边长x/y/z（m） | 相对刚体的中心x/y/z（m） | 相对刚体的旋转x/y/z（度） |
| --- | --- | --- | --- |
| base_link | (0.47,0.30,0.19) | (0,0,0.017) | (0,0,0) |
| left_leg_3 | (0.20,0.07,0.05) | (0.1,0.021,-0.002) | (0,0,-7.505747) |
| right_leg_3 | (0.20,0.07,0.05) | (0.1,0.021,-0.002) | (0,0,-7.505747) |

左右小腿参数相同，按旧URDF原样迁移。URDF角度为rad，-0.131 rad换算为-7.505747度。来源分别为URDF:52–57、170–175、286–291。盒子的长度是完整边长，不是半长。

当前USD这三处还是机身Mesh凸分解、小腿Mesh凸包。关闭额外四处碰撞只使参与碰撞的链接一致，没有使剩余形状一致。本次对照USD与旧URDF的八条主关节零位变换，最大元素误差约2.23e-8，支持直接使用旧link局部坐标；源USD单位为m。

## 4. 可选对照：Lab中的形状存在哪里，怎样改

形状放在实际加载的源USD：Tita_Lab/src/Tita_Lab/assets/data/robots/tita/usd/tita.usd。env_cfg负责选择机器人；tita.py负责资产加载和属性覆盖；具体几何在USD。本次不新增MDP函数或.pyi导出。

在Sim停止播放、打开源USD后，为以下三个刚体各添加一个名为collision_box的Cube子节点：

```text
/TITARobot/Geometry/base_link/collision_box
/TITARobot/Geometry/base_link/left_leg_1/left_leg_2/left_leg_3/collision_box
/TITARobot/Geometry/base_link/right_leg_1/right_leg_2/right_leg_3/collision_box
```

1. Create → Shape → Cube，确认类型是Cube；放到上述位置，直接以刚体节点为父级。
2. Cube的Size设为1.0，将表中完整边长填入Scale；Translate和Rotate填表中局部中心和角度。移动到父级后再输入这些数值，避免保留世界位姿带来的补偿变换。
3. 在Cube上添加Add → Physics → Collider，并确认Collision Enabled开启。已有父级刚体，不给Cube再加RigidBodyAPI或Rigid Body with Colliders Preset。
4. 取消原机身及两个leg_3 Mesh的Collision Enabled，保留视觉Mesh、原刚体、关节、质量、质心及惯量。原Mesh路径分别为三个刚体路径后再加/base_link/base_link或/left_leg_3/left_leg_3、/right_leg_3/right_leg_3。
5. 初次保持box可见，核对其位置；之后可以将box的visibility设为invisible，碰撞继续有效。保存源USD。

Size=1时，缩放后的三条完整边长就是Scale给出的数值；Size若仍为默认2，则尺寸会加倍。保持Cube普通父子变换，不开启resetXformStack，否则它不能按上述局部坐标跟随所属刚体。

新增Cube只提供所属刚体的接触表面。刚体已有显式质量/COM/惯量，不需要按新box重新估算；任务的材质写入和contact/rest offset仍由现有spawn配置与startup事件处理。轮子目前继续使用原Mesh凸包，圆柱迁移仍单独列为待办。

## 5. 采用可选形状方案时怎样检查

使用已有Collider可视化（Viewport眼睛 → Show by Type → Physics → Colliders）检查：机身、两小腿为新box，两轮保留原凸包，leg_1/leg_2没有启用碰撞。再用原单环境zero_agent小运行检查新增形状是否引起异常接触；本步不要求恢复临时打印或另建debug框架。
