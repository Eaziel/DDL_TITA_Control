## 3. 接入中最重要的顺序

```python
# 动作和价值预测已经根据旧obs计算完成。
next_obs, _, rewards, costs, dones, infos = env.step(actions=actions)

# 传入产生本次动作的旧obs；完整11项调用见当前check源码。
storage.add(
    observations=obs,
    actions=actions,
    rewards=rewards,
    costs=costs,
    dones=dones,
    time_outs=time_out_flags,
    reward_values=reward_values,
    cost_values=cost_values,
    log_probs=log_prob,
    action_mean=policy.action_mean,
    action_std=policy.action_std,
)
obs = next_obs
```

先复制这一条经历，再让obs指向后续观测。提前覆盖obs会造成新观测与旧动作配错时刻，shape检查无法识别这种错配。

当前源码在value_networks.eval之后、env.reset之前分配storage，位于inference_mode外。循环内统一取得time_out_flags，保存后更新计数。用户保留了`if "time_outs" in infos`再累加超时的写法，与缺键时采用False标记相容，无需改成候选里的无条件累加。
