# 21 命令死区：将过小的平移速度目标设为零

**阅读目标：** 在原生速度生成器上补齐旧TITA平移死区；结果是每次采样后，模长不超过0.2m/s的(vx,vy)一起归零，wz继续按航向规则更新。

**内容纯AI生成，由人类要求生成，未经人类修改。** 更新：2026-10-25。

## 1. 本次功能与Gym规则

本轮只补一个已有任务规则：在生成目标速度时，若平移速度模长不超过0.2m/s，将vx、vy一起设零。目标转速继续由原有航向规则决定。修改的是任务目标，观测维度、动作维度和关节控制方式保持。

来源为[旧_resample_commands](/home/eaziel/Downloads/tita_rl-master/envs/legged_robot.py:1103)的最后一行：

```python
self.commands[env_ids, :2] *= (
    torch.norm(self.commands[env_ids, :2], dim=1) > 0.2
).unsqueeze(1)
```

这是二维速度向量的模长判断：sqrt(vx²+vy²)>0.2才保留。不是分别判断两列。

| 抽到的(vx,vy)，m/s | 模长 | 处理后的(vx,vy) |
| --- | --- | --- |
| (0.12,0.09) | 0.15 | (0,0) |
| (0.15,0.15) | 约0.212 | 保留 |
| (0.2,0) | 0.2 | (0,0) |

## 2. 实现：继承原生生成器，只增加这一项处理

源码：Tita_Lab/src/Tita_Lab/tasks/velocity/mdp/commands.py。2026-10-25已核实用户写入实现、.pyi导出与CommandsCfg引用；当前配置导入/validate及class_type身份检查通过，尚未运行新仿真。下方保留原方案参考，当前源码逐字摘录见对应commands.py说明。

```python
# Copyright (c) 2022-2026, The Isaac Lab Project Developers (https://github.com/isaac-sim/IsaacLab/blob/main/CONTRIBUTORS.md).
# All rights reserved.
#
# SPDX-License-Identifier: BSD-3-Clause

from __future__ import annotations

from collections.abc import Sequence

import torch

from isaaclab.envs.mdp.commands import UniformVelocityCommand, UniformVelocityCommandCfg
from isaaclab.utils import configclass


class TitaVelocityCommand(UniformVelocityCommand):
    """Velocity commands with the legacy TITA planar speed deadband."""

    cfg: TitaVelocityCommandCfg

    def _resample_command(self, env_ids: Sequence[int]) -> None:
        """Sample velocity commands with a planar speed deadband."""
        super()._resample_command(env_ids)

        # 命令缓冲为(N, 3)，每行[vx, vy, wz]；这里取本次重采样的M行。
        vel_xy = self.vel_command_b[env_ids, :2]  # (M, 2)，单位m/s。
        speed_xy = torch.linalg.vector_norm(vel_xy, dim=1)  # (M,)。

        # 沿用旧Gym：速度模长大于阈值（默认0.2 m/s）才保留平移命令。
        moving = speed_xy > self.cfg.lin_vel_deadband  # (M,)，bool。

        # (M, 1)广播到两列；将处理后的结果写回原始命令缓冲。
        self.vel_command_b[env_ids, :2] = vel_xy * moving.unsqueeze(1)


@configclass
class TitaVelocityCommandCfg(UniformVelocityCommandCfg):
    """Configuration for TITA velocity commands."""

    class_type: type[TitaVelocityCommand] = TitaVelocityCommand
    lin_vel_deadband: float = 0.2
    """Planar command speeds at or below this threshold are zeroed [m/s]."""
```

TitaVelocityCommand是实际执行计算的类；TitaVelocityCommandCfg保存配置，class_type指定CommandManager要创建的实现类。父类构造函数继续创建vel_command_b、heading_target、计时器和统计；本轮不新建这些状态。

_resample_command是原生CommandTerm约定的重采样钩子。先调用super让父类抽到本轮目标，再处理新目标。若把super放在处理之后，父类会把刚处理的值覆盖。每回合reset与计时器到期均经原生_resample调用这个钩子，故只补一处。

vel_command_b为(N,3)，永久保存在生成器实例上；env_ids选择这次需要换目标的M个环境。vel_xy是(M,2)，speed_xy和moving是(M,)；moving.unsqueeze(1)为(M,1)，乘法广播到两列。最后用索引赋值写回原缓冲。env_ids是高级索引时，不能只修改取出来的副本并期待原缓冲改变。

lin_vel_deadband默认0.2m/s，作为cfg字段可以显式写在环境配置中。它只作用于平移速度模长，heading_target和wz继续使用父类实现；得到零平移目标时仍可能需要原地转向。

## 5. 数据怎样被使用

CommandManager创建的对象保存在_terms["base_velocity"]。原生get_command("base_velocity")返回该对象.command；继承的command属性直接返回vel_command_b。

当前三处消费端为：

| 消费端 | 获取的内容 |
| --- | --- |
| policy中的velocity_commands | 目标[vx,vy,wz]，随后乘现有scale=(2,2,0.25) |
| tracking_lin_vel/ang_vel奖励 | 原始物理单位的目标，与机器人实际速度比较 |
| terrain_levels_vel课程 | 原始vx、vy，计算降级所用的目标移动距离 |

例如抽到(0.12,0.09)时，目标平移被改为(0,0)。policy的对应两列为零；平移追踪奖励评价零平移目标；课程的平移命令模长也为零。若此刻航向外环给出wz=0.4rad/s，目标仍可为(0,0,0.4)，policy第三列经0.25缩放为0.1。

仅修改观测会留下奖励或课程仍读未处理目标的问题；这里修改命令源，消费者按各自既定时机获取同一生成器的数据。调用时序仍继承Lab：本轮没有把命令更新移动到旧Gym奖励前的位置，不将数值规则对齐冒充整个step时序已对齐。
