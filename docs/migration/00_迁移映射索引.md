## 4. 使用这张表时怎样查证

先看 TITA 子类覆盖值，再补父类默认值，最后看实际执行分支。一个字段被声明，不代表执行代码一定读取；地形中已注释的比例分支就是例子。

旧 `legged_robot.py` 是完整环境执行器：既创建场景，又组织step/reset，还计算命令、观测、奖励与成本。迁到 Lab 后，这些职责分别进入配置、官方manager、MDP函数和必要的自定义状态对象，不要求文件一一对应。

需要保留的跨模块差异包括：

- 旧URDF只有5个碰撞形状，当前USD静态检查为9个，接触行为还需对照。
- 粗糙地形使用平台出生原点，不能把 `env_spacing` 直接当平台大小；平地分支与粗糙地形分支要分开看。
- 旧轮子force sensor与刚体接触力不同；传感器声明也不会自动成为观测。
- 旧回调的命令、高度、推扰分别迁到Commands、Scene/MDP、Events，详见 [04第3节](04_commands迁移.md#3-为什么这样迁移)。

每次只定向核对当前功能；接通各块后，再按本表做跨模块检查和小规模运行。遇到问题再排障是补充手段，不能替代这份覆盖记录。
