## 2. Gym怎样使用环境返回值

旧`OnConstraintPolicyRunner`采样时接收：

```python
obs, privileged_obs, rewards, costs, dones, infos = self.env.step(actions)
critic_obs = privileged_obs if privileged_obs is not None else obs
```

六项位置固定；cost独立于reward。第二项为None时，runner使用obs作为critic输入，模型内部再按规则切片。

Lab的接口为：

```python
observations, rewards, terminated, truncated, extras = env.step(actions)
```

训练接口转换必须显式完成：

| Lab返回 | wrapper交给旧训练侧 | 理由 |
| --- | --- | --- |
| 五组观测字典 | `(N,586)` obs | 旧模型按连续列切片，需要明确布局 |
| 无独立第二观测矩阵 | None | 586内已经包含价值/辅助所需额外信息，runner有回退规则 |
| reward `(N,)` | 原样传递 | 环境已完成权重、dt和最终合成 |
| extras["costs"] `(N,6)` | 独立cost张量 | 环境已乘一次dt并保存终止步副本 |
| terminated/truncated | done整数与infos["time_outs"] | 存储需要结束标志，算法还需区分超时 |
| extras["log"] | infos["episode"] | 适配旧回合日志读取名称 |

## 3. Lab怎样实现这层转换

文件位于`Tita_Lab/src/Tita_Lab/learning/np3o/env_wrapper.py`。`tasks`负责环境，`learning`负责使用环境数据的训练实现。这是项目组织选择，不是Lab强制目录。

包装器通过普通import供未来入口使用，不是MDP项，无需在env_cfg或mdp/.pyi登记。当前尚没有接通的NP3O启动脚本；导入包含仿真任务的模块时仍遵守Lab的启动顺序。

五组布局：

$$
33+187+6+30+330=586.
$$

顺序为policy/scan/privileged_state/dynamics/history，区间为0:33、33:220、220:226、226:256、256:586。沿列拼接后裁剪到±100，内部历史不因此被原地裁剪。

结束标志逐环境计算：

$$
\mathrm{done}_n=\mathbf1\{\mathrm{terminated}_n\lor\mathrm{truncated}_n\}.
$$

cost不重新读取物理状态、不再乘dt或k。Lab已经自动reset结束的行，wrapper不再次reset；本步reward/cost属于刚结束回合，对应返回观测可能已经是新回合初始值。

## 4. 为什么这样迁移

环境计算、训练采样与算法更新分别维护。这样能继续使用Lab场景和管理器，同时逐项核对旧训练的数据约定。官方RslRlVecEnvWrapper也承担接口适配，但它服务当前RSL-RL返回约定，不能直接替代本项目的六项cost接口。

本文件只使接口具备可接入的形式。完整NP3O还需价值模型、分布、存储、算法、runner和入口；定义wrapper不会改变任务注册的default_agent，也不会自动启动训练。
