## 2. Gym怎样判定

来源：[旧_update_terrain_curriculum](/home/eaziel/Downloads/tita_rl-master/envs/legged_robot.py:1119)。核心规则为：

```python
distance = torch.norm(
    self.root_states[env_ids, :2] - self.env_origins[env_ids, :2], dim=1
)
move_up = distance > self.terrain.env_length / 2
move_down = (
    distance < torch.norm(self.commands[env_ids, :2], dim=1)
    * self.max_episode_length_s * 0.5
) * ~move_up
self.terrain_levels[env_ids] += 1 * move_up - 1 * move_down
```

distance是机器人当前xy位置与本回合地形出生原点的直线距离，不是整段轨迹长度。使用的是地形原点，因此出生时额外的随机xy偏移也计入这个差值。

本项目每块8m，升级阈值为4m。降级阈值是命令平移速度大小乘最大回合20s，再乘0.5。它用最大回合长度，不用本次实际存活秒数；已满足升级的机器人不会同时降级。

例如命令(vx,vy)=(0.3,0)m/s，降级阈值为3m：

| 回合结束距离 | 下一回合等级 |
| --- | --- |
| 1m | 减1 |
| 3.5m | 保持 |
| 4.5m | 加1 |

距离恰好等于阈值时按源码的严格比较处理。等级最低为0；从9升级到10时随机选回0~9。列编号不变，所以仍保持对应地形类型。

把判定与行号更新写成公式，便于与代码对应。$D$ 是结束位置到地形原点的水平距离，$L_x=8\mathrm m$，$T_{max}=20\mathrm s$：

$$
u=\mathbf1\{D>L_x/2\},\qquad
v=\mathbf1\{D<0.5T_{max}\lVert\mathbf v_{xy,cmd}\rVert_2\}\,(1-u),
$$

$$
\ell_{next}=\ell+u-v.
$$

随后再处理最低级截断与越过最高级后的随机重分配。这里 $\ell$ 是地形行号，与动作延迟选择编号是两个不同变量。

## 5. 谁调用它，为什么在这个时候

原生[ManagerBasedRLEnv._reset_idx](/home/eaziel/IsaacLab-main/source/isaaclab/isaaclab/envs/manager_based_rl_env.py)第一项调用为：

```python
self.curriculum_manager.compute(env_ids=env_ids)
```

此时机器人和命令仍保存上一回合末尾的数据。CurriculumManager遍历配置中的课程项，执行：

```python
state = term_cfg.func(self._env, env_ids, **term_cfg.params)
```

terrain_levels_vel算出升降标志，TerrainImporter更新等级与env_origins；随后原生环境执行Scene reset和reset Events，机器人才按新原点复位。CommandManager稍后重采样下一回合命令，因此课程读取旧命令。只更新这次env_ids中的机器人。

本项目已有TitaVelocityEnv._reset_idx最终调用super()._reset_idx，所以登记配置后就会进入这条原生路径。不需要手动在子类再调用课程，否则可能一回合更新两次。

返回的平均等级由管理器写入extras["log"]["Curriculum/terrain_levels"]。原生实现平均的是全部环境的等级，而不是仅本次重置的环境。

## 补充问答

**Q：** 升级降级指的是啥？让地形对于任务来说更简单？

**A：** 对，降级让下一回合使用较容易的地形，升级让下一回合使用较难地形。这里等级就是每台机器人各自的地形行号0~9，难度由台阶落差定义；正台阶随等级增加更高，负台阶随等级增加更深。地图在启动时已生成，课程把下一回合出生点换到另一行，不在机器人运动过程中修改脚下网格。类型列保持，奖励公式沿用原配置。例如当前等级5，降级后变4，下回合reset时按terrain_origins[4, terrain_type]放置机器人。
