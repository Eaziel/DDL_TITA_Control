## F1 扫描器子节点没有创建，阻断初始化

### 当前代码与问题

当前Scene写的是：

```python
height_scanner = RayCasterCfg(
    prim_path="{ENV_REGEX_NS}/Robot/Geometry/base_link/height_scanner",
    # 其他字段省略。
)
```

该子节点不在USD中。RayCasterCfg确实声明默认spawn=SensorFrameCfg()，文档称会生成Xform；但当前本地PhysX链是InteractiveScene→RayCaster→BaseRayCaster→SensorBase，这些构造路径没有调用它的spawn。ReplicateSession负责规划和复制已有源，不会代替生成这个源prim；当前单变体场景使用整env根的同质克隆，也不会凭空生成此子节点。

随后_PhysXRayCasterMixin._initialize_pose_tracking()调用resolve_matching_prims_from_source()，查询已有节点，复现结果是：

```text
No prim found at '/TITARobot/Geometry/base_link/height_scanner'.
```

这是配置说明与当前实现链之间的缺口。此前解释“默认配置会创建，因此该后缀正确”跳过了执行验证，应纠正。

### 建议修正

在env_cfg.py的height_scanner配置中改两项，其他扫描参数保留：

```python
height_scanner = RayCasterCfg(
    prim_path="{ENV_REGEX_NS}/Robot/Geometry/base_link",
    spawn=None,  # Track the existing base body; no extra sensor prim is required.
    update_period=0.01,
    offset=RayCasterCfg.OffsetCfg(pos=(0.0, 0.0, 20.0)),
    ray_alignment="yaw",
    pattern_cfg=patterns.GridPatternCfg(
        resolution=0.1,
        size=[1.6, 1.0],
        ordering="yx",
    ),
    debug_vis=False,
    mesh_prim_paths=["/World/ground"],
    global_world_only=True,
)
```

本地实现寻找刚体祖先时包含prim自身，因此已有base_link可以直接提供位姿。配置docstring关于spawn=None的限制也与这段实现不完全一致；此建议以本地实际跟踪方法为依据。CPU最小复现已验证修正后的位姿解析，尚未运行真实射线/物理环境。

依据：[RayCasterCfg](/home/eaziel/IsaacLab-main/source/isaaclab/isaaclab/sensors/ray_caster/ray_caster_cfg.py)、[Scene创建传感器](/home/eaziel/IsaacLab-main/source/isaaclab/isaaclab/scene/interactive_scene.py)、[PhysX位姿跟踪](/home/eaziel/IsaacLab-main/source/isaaclab_physx/isaaclab_physx/sensors/ray_caster/ray_caster.py)、[祖先查询包含自身](/home/eaziel/IsaacLab-main/source/isaaclab/isaaclab/sim/utils/queries.py)。

## F2 PhysX没有继承旧关节速度上限

### 两边有什么不同

旧有效URDF设置六腿关节velocity=25、两轮velocity=20，单位rad/s。当前USD保存了newton:velocityLimit，数值约1432.39、1145.92 deg/s，但没有physxJoint:maxJointVelocity；Newton属性不会自动成为PhysX约束。

当前执行器joint_velocity_limit=None。原生ActuatorCollection此时保留后端读到的默认值；本地PhysX schema的关节速度默认值为inf，不能据USD中出现“velocityLimit”认定已保留25/20。

### 建议修正：两个位置，四组配置

资产配置与Scene任务配置各有一份actuators字典。Scene会整体覆盖资产的字典，所以两处都补，避免只修独立导入脚本：

```python
# assets/tita.py: retain the existing gains and effort limits in each group.
"legs": IdealPDActuatorCfg(
    joint_names_expr=["joint_.*_leg_[123]"],
    stiffness=40.0,
    damping=1.0,
    actuator_effort_limit=60.0,
    joint_effort_limit=60.0,
    joint_velocity_limit=25.0,  # Solver-level joint speed limit [rad/s].
),
"wheels": IdealPDActuatorCfg(
    joint_names_expr=["joint_.*_leg_4"],
    stiffness=0.0,
    damping=0.5,
    actuator_effort_limit=15.0,
    joint_effort_limit=15.0,
    joint_velocity_limit=20.0,
),
```

```python
# env_cfg.py / VelocitySceneCfg.robot.actuators
"legs": TitaPDActuatorCfg(
    joint_names_expr=["joint_.*_leg_[123]"],
    stiffness=40.0,
    damping=1.0,
    actuator_effort_limit=60.0,
    joint_effort_limit=60.0,
    joint_velocity_limit=25.0,
),
"wheels": TitaPDActuatorCfg(
    joint_names_expr=["joint_.*_leg_4"],
    stiffness=0.0,
    damping=0.5,
    actuator_effort_limit=15.0,
    joint_effort_limit=15.0,
    joint_velocity_limit=20.0,
    scale_effort_with_kp=True,
),
```

使用joint_velocity_limit设置求解器约束。actuator_velocity_limit属于执行器模型参数，IdealPD本身不会因此建立电机转矩—转速曲线，不能混为一项。上述候选配置已通过validate，真实后端读数仍待初始化后核实。

依据：[旧URDF](/home/eaziel/Downloads/tita_rl-master/resources/tita/urdf/tita_description.urdf:118)、[ActuatorBaseCfg](/home/eaziel/IsaacLab-main/source/isaaclab/isaaclab/actuators/actuator_base_cfg.py)、[属性解析](/home/eaziel/IsaacLab-main/source/isaaclab/isaaclab/actuators/actuator_collection.py)。

## F3 刚体阻尼和速度参数遗漏

旧Gym的父类asset配置还设置linear_damping=0、angular_damping=0、max_linear_velocity=1000、max_angular_velocity=1000。当前USD没有这些PhysX属性，tita.py只覆盖max_depenetration_velocity。

本地PhysX schema默认angularDamping=0.05，最大刚体角速度约5729.58 deg/s，即100 rad/s。这些是刚体参数，与PD中的Kd不是同一个物理环节。此前只迁sim.physx块，漏掉了asset块中的这些参数。

在assets/tita.py顶部增加import math，并用下面内容替换现有rigid_props：

```python
import math
```

```python
rigid_props={
    "/.*": [
        PhysxRigidBodyCfg(
            linear_damping=0.0,
            angular_damping=0.0,
            max_linear_velocity=1000.0,  # [m/s], matching the Gym asset option.
            max_angular_velocity=math.degrees(1000.0),  # This USD field uses deg/s.
            max_depenetration_velocity=1.0,
        )
    ]
},
```

注意单位：旧Gym选项的角速度是rad/s，本地PhysxRigidBodyCfg.max_angular_velocity明确使用deg/s；不能直接填相同的1000。关节执行器joint_velocity_limit仍用rad/s，属于另一接口。

配置校验通过；这项修正只补齐已知参数，不声称两个PhysX版本的动力学必然相同。是否实际达到这些很高的上限还取决于运动，角阻尼差异则可直接改变运动。

依据：[旧asset配置](/home/eaziel/Downloads/tita_rl-master/configs/legged_robot_config.py:117)、[本地PhysxRigidBodyCfg及单位](/home/eaziel/IsaacLab-main/source/isaaclab_physx/isaaclab_physx/sim/schemas/schemas_cfg.py)。默认值直接读取本机安装包的generatedSchema.usda，见证据JSON。

## F4 资产、接触和高度采样的差异

九个刚体质量也与旧URDF合并固定关节后的值逐体核对，最大浮点差约1.91e-7 kg；[质量对照](../audits/2026-10-20_kp/asset_mass_comparison.json)。这项相符不消除以下几何和传感器差异。

1. **碰撞几何：** 当前USD有9个碰撞体；旧有效URDF仅base、两条leg_3和两轮，共5个。额外四个属于左右leg_1/leg_2，可能改变自碰撞和触地。用户验证“关节可运行”没有覆盖这一点。是否严格复刻原碰撞配置应单独决定，不能擅自删用户资产。
2. **接触力：** 旧Gym读取net_contact_force，当前Lab读取net_normal_forces_w；任务函数的范数/阈值计算一致，不代表输入向量物理含义完全相同。摩擦切向分量、采样窗口与接触对仍需物理对照。
3. **高度：** 187点数量/顺序对应，但Gym查相邻高度格最小值，Lab与三角网格求交；台阶边缘数值可能不同。
4. **惯量：** Lab质量随机化按质量比缩放惯量，COM另加偏移；旧Gym内部recomputeInertia未复现。材质恢复合成同样没有旧二进制实测。

本轮没有误判两处可用实现：接触传感器会遍历Robot下的嵌套刚体，短路径不要求刚体都在直接子层；本地PhysX schema的自碰撞默认值为True，不能拿别的版本默认值报告“自碰撞没开”。

## F6 模型和训练仍是后续工作

旧完整观测为33当前帧+187高度+36特权量+330历史=586维。当前Lab提供33和330两组，PPO模板的actor/critic均只读policy。历史缓存存在并不意味着网络已经使用它。

Cost、NP3O、Barlow Twins/encoder和runner接口尚未迁；现有普通PPO不是原训练算法。软关节位置限制系数旧值0.9，目前资产默认1.0；当前奖励未启用相关项，迁Cost时须处理，不能为了Cost简单改掉reset采样含义。模板中cartpole名称等也应在训练配置阶段整理，当前不将其当成PD实现错误。
