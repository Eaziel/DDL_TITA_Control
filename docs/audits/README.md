## 补充问答

**Q：你一直说的cpu检查是啥？**

**A：** “CPU检查”是本项目对一类验证方式的简称，不是Isaac Lab的API。使用CPU上的张量运行Python/PyTorch代码，检查公式、shape、索引、数据传递与部分调用逻辑。每项结果还需具体区分：

| 本项目例子 | 实际执行了什么 | 结论边界 |
| --- | --- | --- |
| 当前命令接线 | 导入当前配置、validate、断言class_type是TitaVelocityCommand | 配置选到了正确类；未创建真实物理环境 |
| 命令数值对照 | 原生命令reset/compute配CPU机器人状态替身，比较旧死区公式 | 给定状态下的逻辑与数值；不是实际机器人运动 |
| 包装接口 | 用替身环境返回张量和结束标志，执行真实拼接与候选包装 | 输入输出与传递规则；不证明物理reset正确 |
| 动作网络 | 实际旧PyTorch层与候选层在CPU算前向及一次梯度 | 该子网给定参数/输入下数值一致；不是优化器更新或训练 |

例如CPU张量[0.12,0.09]模长0.15，应被死区函数归零。这可以实际执行并检查，不需要在Sim里生成机器人。反过来，是否与地面正确碰撞、传感器返回何种力、GPU运行是否正常、训练能否平衡，必须有相应运行证据。

CPU也能用于物理仿真，因此“用CPU”本身不代表“没仿真”；本索引各次明确注明是否启动Sim、哪些对象是替身。源码静态检查又是另一类证据，例如仅用AST读取代码不会执行函数。判断结论应看每份检查的具体范围。
